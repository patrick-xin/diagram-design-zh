# 矩形树图（Treemap）

**最适合**：部分与整体，且**相对大小就是故事**——磁盘与依赖包占用、预算拆分、市场份额、人口、时间分配。一个总量分解成数块、读者的问题是「谁占大头、大多少」时用。

不用它：排名清单且精确值比占比重要（**柱状图**）；表达包含 / 作用域但没有数量（**嵌套图**）；需要逐层追父子路径（**树形图**）。

## 布局惯例

- **绘图区**：`0 0 1000 500` viewBox 内 x 40→956、y 40→420——与柱状 / 折线 / 散点同一条竖向节奏，图例块落在读者已习惯的位置（发丝线 y=462、`LEGEND` 478、条目 492）。
- **Squarified 布局**（Bruls 等，2000）：降序排列，每行贴剩余矩形的**短边**排。长宽比保持接近 1，两块面积才能用眼睛比。**绝不排成简单条带**——细长条没法比。
- **格子数**：4–8。超过 8，尾部变成没法标注的细条——把尾部并进一个明确的「其他」格，并在数据源行写明含什么。
- **4px 网格**：格边像一切元素一样贴网格，格间 4px 泳道。贴格与泳道都会挪面积，所以交付前要核——按**相对误差**核（`(绘制 − 真实) ÷ 真实`），不看百分点。59% 的格差 0.1pp 无所谓，0.5% 的格差 0.1pp 就是四分之一。每格控制在真实占比的几个百分点内（官方示例最差 2.7%，正是那条细格——网格做不到更好），并把编码写进数据源行（`面积 = 存储量`）。
- **填充**：按名次排的 `ink` 透明度梯——档位 = style-guide α 梯子的图表特例 `{0.16, 0.13, 0.11, 0.09, 0.07, 0.04}`，六档整组使用（值编码面积深度，不许单抽一档、不许发明组外档）——非焦点的次序在灰度打印和色弱读者下都活着。焦点格至多一个——**编辑上**最值得看的那块，不自动等于最大的。注意焦点格被摘出了色梯，灰度下落在哪算哪；靠 `accent` 描边识别它，绝不让色阶承载面积以外的含义。
- **描边**：每格 1px `ink @ 0.30` 发丝线；焦点格 1.5px `accent`。
- **标签放格内**，左上角、离边 16px：格名中文 sans 14px 600（窄格 12px），下一行数值 mono 9px。按格大小分四档：
  - 大格——名 + 值 + 占比（`4.78 TB · 59%`）
  - 中格——名 + 值
  - 小格——一个诚实的短缩写
  - 细条——**不放字。** 格子至少 12×12px 时，格心放一个实心 `ink` 圆点 `r=5`、内嵌 paper 色 `i`，格名与占比写进图例；两边都不足 12px 就省掉格内标记，靠图例里的位置说明。定尺寸的圆点绝不许压格边。**不要为塞下标签旋转文字**：五个正字里躺一个侧字，读者先看到失误再看到数据；而且 `text-anchor="middle"` 沿基线居中，转 90° 后基线映到长轴，窄轴方向没有任何东西在居中。
  - 绝不为标签缩格。格的大小是数据，标签是注解。
- **对比度**：按实际交付的 token 算天花板。数值行是 mono 9px `muted` 不是 `ink`——`muted` 需要比 `ink` 更浅的格底：对着合成后的填充实测，浅色档色梯顶部到 **0.16**、深色档到 **0.14** 就跌破 4.5:1（`ink` 能忍到 0.20——查错 token 恰好会写下这个数）。中间调填充（实心 accent 或 50% ink）对深浅文字都挂；用「淡染 + 描边」套路。数据源行同样用 `muted`：`soft` 在纸上只有 3.48:1，在这条色梯上到不了 AA。
- **图例**：标准块（发丝线、`LEGEND`、条目）——点名焦点格、色梯方向、带信息圆点的格。数据源行与 `LEGEND` 同行右对齐 mono 9px，写清面积编码的是什么 + 数据集与日期。

### 格元素范式

```svg
<!-- 格体（浅色档） -->
<rect x="X" y="Y" width="W" height="H" rx="2"
      fill="rgba(41,49,79,0.16)" stroke="rgba(41,49,79,0.30)" stroke-width="1"/>
<text x="X+16" y="Y+28" fill="#29314f" font-size="14" font-weight="600"
      font-family="'MiSans', 'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei', sans-serif">格名</text>
<text x="X+16" y="Y+46" fill="#565e7e" font-size="9"
      font-family="'Sarasa Mono SC', ui-monospace, monospace">VALUE · SHARE</text>
```

焦点格：填充换 `accent@0.15`、描边换 `accent` 1.5px。

## 诚实数据规则

**面积是唯一编码。** 不裁切、不设下限、不取对数来让格子可见；也不因为格子小就删格——树图声称展示一个整体，少一块图就在撒谎。小到没法标注的部分给图例条目，格内只在装得下时给信息圆点；小到画不出的部分并成一个诚实的、有名字的「其他」。好几块在目标尺寸下都看不见，说明这份数据想要的是柱状图。

最小格盯最紧：贴格与泳道对它扭得最狠，也最没人核。展示的**舍入**同样要防：六个值各自进位，加起来可能超过你印在下面的总量。要么保留足够精度让各部分对得上账，要么在数据源行直说（`数值经舍入，合计可能有出入`）。

## 反模式

- 超过 8 格没有「其他」桶（细条没法标注）。
- 各格加起来不等于声称的总量；百分比列合计不是 100。
- 条带布局而非 squarified——面积对比失效。
- 彩虹填充：一格一色毁掉名次阅读和单焦点规则。
- 静态图里嵌套超过两层；第二层要更重的边框和自己的标签档，第三层没有交互就读不了。
- 3D 或带阴影的格——面积已经是全部信息了。
