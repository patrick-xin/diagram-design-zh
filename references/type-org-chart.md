# 组织架构图（Org Chart / Responsibility Map）

**最适合**：人类团队、Agent 团队、客服升级路径、角色归属、路由地图——读者要知道**谁拥有什么**而不只是父子结构的任何层级。

节点是人 / Agent / 团队 / 角色 / 责任人时用组织架构图，别用树形图：树只展示层级，组织图展示归属、调用路径与覆盖缺口。

## 布局惯例

- 根 = 总负责人或「前门」，顶部居中。**唯一焦点节点**给接收模糊工作的那个人 / 团队 / Agent。
- 一级节点 = 部门、小组、队列或主要路由分桶，水平对齐。
- 二级节点 = 具体负责人或专家。专家超过 8 个时归到小组节点下，不排一条长龙。
- **画布宽度先按最宽一层算够**：盒数 × 盒宽 + 同层间隙（≥24px）+ 两侧边距，装不下就砍节点或换更宽 viewBox——盒子叠盒子是硬伤，不许硬塞。
- 分区标签（负责人层 / 小组层 / 专席层，左缘 sans 10px · 0.25em）+ 两条分区横线把三层分开。
- 正交连接线：父垂竖线 → 横总线 → 垂到各子节点上边中点。无斜线，端点压准盒中心。
- 空间允许时每个节点回答三个问题：
  1. **名字**——人 / 角色 / Agent，中文 sans 12–14px 600，全图统一一档。
  2. **怎么调用**——群_handle、队列、工单前缀或触发条件，mono 10px。
  3. **管什么**——2–4 个词的所有权短语，中文 sans 12px，不写成段落。
- 未接入 / 未上线的信息用虚线 optional 样式标出，**不要藏起来**——缺失的路由是运营信息。
- 升级 / 审批规则放小侧注或底部条，不加成组织节点。

## 节点样式

- **前门 / 指挥中心**：焦点处理（`accent-tint` 底 + `accent` 描边）。
- **团队 / 小组 / 部门**：backend 处理（纸色底 + `ink @ 0.40` 描边）。
- **个体 Agent / 负责人**：按是否在系统内取 store 或 external 处理。
- **缺口 / 待建**：optional 虚线处理。
- **审批闸门**：security 处理，独立于汇报层级。

## 复杂度预算

- 可见组织节点 ≤12；更多就拆一张总览 + 各小组细节图。
- 深度 ≤4 层。
- 单个父节点直接下属 ≤5；更多就加分组节点。
- 焦点节点 ≤1——组织图的职责是清晰，不是处处高亮。
- 侧注 ≤2。

## 反模式

- 用户真正的问题是「谁干什么」却画了泳道图。泳道讲流程，组织图讲归属。
- 画布不够宽却硬塞——同层盒子重叠比砍节点更伤。
- 每个人 / Agent 画成一模一样的盒子——前门、专家、缺口、升级路径全被抹掉。
- 节点里塞完整岗位说明。所有权短语要短，细节挪到下方摘要卡。
- 不可用 / 未接线的 Agent 画成正常在岗（用虚线 optional 让缺口可见）。
- 正文段落里重复群_handle（节点副标已经承载了调用方式）。
- 图例飘在组织结构区里。用标准底部图例条。
