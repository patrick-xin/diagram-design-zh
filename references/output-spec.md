# 输出规格——格式 × 尺寸 × 细节 × 受众

四个刻度盘决定一次产出长什么样。**动笔前设定**——它们改变交付物、布局、类型坡道、节点数和措辞，事后补设等于重画。适用于每一次画图请求，包括对已有图的重绘与导入重绘。

| 刻度盘 | 回答的问题 | 默认 |
|---|---|---|
| **格式** | 这个文件落到哪里？ | `html` |
| **尺寸** | 画布多大？读者离多远？ | `doc-inline` |
| **细节级别** | 每个元素都保留，还是压缩？ | `balanced` |
| **受众** | 措辞多技术？ | `mixed` |

请求里能推断的直接推断（"放进我的 PPT"= slide 预设）。仍有实质性含糊就问一个简短问题。用户不在乎就用上面的默认值，并说明用了哪几个。

---

## 1. 格式

| 格式 | 交付物 | 保留 | 丢弃 |
|---|---|---|---|
| `html` | 自包含 `.html`（默认） | 页眉、图、摘要卡、页脚、在线字体 | 无 |
| `svg` | 源文件旁的 `.svg` | `<svg>` 节点、矢量文字 | 讲解包装；离线工具里字体会被替换 |
| `png` | 按 `device_scale_factor` 的 `.png` | 浏览器渲染的像素 | 矢量可编辑性 |
| `html+png` | 两者都要 | — | — |

**永远先生成 HTML**——`svg` 和 `png` 都从它经 [`export.md`](export.md) 产出。绝不手写 SVG 文件；HTML 是唯一事实来源，也是质量门（SKILL.md §10）唯一的校验对象。

按投放地选：

| 投放地 | 格式 | 尺寸预设 |
|---|---|---|
| 公众号文章、博客、README | `html`（嵌入）或 `png` | `doc-inline` |
| PPT / Keynote / 演讲投屏 | `png` @2 | `slide-16x9` |
| Figma / Illustrator / 二次编辑 | `svg` | `fit` |
| X / OG 链接卡 | `png` @2 | `social-og` |
| 打印讲义、PDF | `png` @3 | `print-a4-landscape` |
| 公众号封面头图 | `png` @2 | `wechat-cover` |
| 小红书图文 | `png` @2 | `xiaohongshu-3x4` |
| Confluence / Notion / 语雀 / 飞书文档 | `png` @2 | `doc-wide` |

---

## 2. 尺寸

预设决定 SVG `viewBox`。下表每个值都能被 4 整除，SKILL.md §9 的网格规则仍然成立。

| 预设 | viewBox | 宽高比 | PNG @2 | 类型坡道 | 用途 |
|---|---|---|---|---|---|
| `doc-inline`（默认） | `0 0 1000 600` | 5:3 | 2000×1200 | standard | 文章 / README 正文宽度的图 |
| `doc-wide` | `0 0 1280 720` | 16:9 | 2560×1440 | standard | 全宽文档、wiki 页 |
| `slide-16x9` | `0 0 1280 720` | 16:9 | 2560×1440 | presentation | 幻灯片、投屏 |
| `slide-4x3` | `0 0 1024 768` | 4:3 | 2048×1536 | presentation | 老式模板 |
| `social-og` | `0 0 1200 632` | ~1.9:1 | 2400×1264 | presentation | 链接预览卡 |
| `social-square` | `0 0 1080 1080` | 1:1 | 2160×2160 | presentation | 信息流帖、轮播 |
| `wechat-cover` | `0 0 900 380` | ~2.35:1 | 1800×760 | presentation | 公众号封面头图 |
| `xiaohongshu-3x4` | `0 0 1080 1440` | 3:4 | 2160×2880 | presentation | 小红书图文 |
| `print-a4-landscape` | `0 0 1120 792` | ~1.41:1 | @3 → 3360×2376 | print | A4 横向，96dpi 下 ~10mm 边距 |
| `print-letter-landscape` | `0 0 1056 816` | ~1.29:1 | @3 → 3168×2448 | print | US Letter 横向 |
| `fit` | 由内容推导 | 任意 | @2 | standard | 矢量交接；无固定框 |

### `fit` 的推导

内容包围盒**向上**取整到 4 的倍数，再加固定镶边：四面 40px 外边距，底部另加 60px 给图例条。内容永远不许贴 viewBox 边。

### 按尺寸级别的字号坡道

画布变大，节点名会相对变小——抵抗这个。坡道随预设缩放，投影幻灯从最后一排也要读得清。**中文字号下限（≥10px）在任何坡道都不放宽**：拉大画布，不缩小汉字。

| 角色 | standard | presentation | print |
|---|---|---|---|
| 页面标题（serif 400） | 28 | 40 | 32 |
| 节点名（sans 600） | 14 | 18 | 14 |
| 子标签 · 中文（sans） | 12 | 14 | 12 |
| 子标签 · 拉丁技术串（mono） | 9 | 12 | 9 |
| 箭头标签 · 中文（sans） | 12 | 14 | 12 |
| 箭头标签 · 拉丁（mono） | 8 | 12 | 8 |
| eyebrow · 拉丁 mono / 中文 sans | 8 / 12 | 8 / 12 | 8 / 12 |
| 节点盒最小高度 | 48 | 64 | 48 |
| 节点最小间距 | 24 | 40 | 24 |

presentation 坡道意味着更少的节点——64px 盒子里的 18px 名称吃画布。`slide-16x9` 塞不下时，是尺寸盘在告诉你细节盘开太高了；降一级细节，别缩字号。

### 安全区

- **所有预设**：40px 外边距；图例条占底部 60px，别的东西不进。
- **`social-og` / `wechat-cover`**：四面外圈 64px 保持净空——平台裁切不可预测。
- **`slide-*`**：模板有页脚栏时底部 80px 净空；不确定就问。

## 3. 细节级别

源内容有多少能活下来。这是**数量**盘——管多少个元素通过，不管它们叫什么（那是 §4）。

| 级别 | 节点 | 连线 | 子标签 | 活下来什么 |
|---|---|---|---|---|
| `faithful`（详尽） | ≤24，分区 | ≤32 | 每个端口、协议、版本 | 源里每个独立组件。只有完全重复的才合并。 |
| `balanced`（默认） | ≤12 | ≤16 | ≤4 个节点带技术子标签 | 承载故事的主干；叶子簇各折叠成一个节点。 |
| `simplified`（简略） | ≤7 | ≤9 | 无 | 能力与先后顺序。基础设施消失。 |

`balanced` 和 `simplified` 落在标准复杂度预算之内（SKILL.md §9：节点 ≤9；`balanced` 的上限 12 是压缩外部源时的许可弹性，9–12 之间时每个节点都要挣自己的位置）。**`faithful` 有意超预算**——这是交易，附带条件：

1. **分区强制**。超过 9 个节点，每个节点归入一个带标签的区（2–4 个区，细线边框、`paper-2` 底，区标签在左上角：中文 sans 12px · 0.3em，纯拉丁 mono 8px + uppercase）。不分区的 20 节点图是接线图，不是示意图。
2. **连接线规则不放松**。SKILL.md §8 在 24 节点下全部适用。布不下还不重叠，就是真超上限了——拆。
3. **超过 24 个节点，拆**。产出一张总览（区作节点，`balanced` 语法）+ 每区一张细节图。命名 `<base>-overview.html`、`<base>-<zone>.html`。永不交付 40 节点单画布。
4. **accent 仍是 ≤2**。节点变多买不来更多焦点。

### 降级梯子

源内容超过级别允许的量时，按此顺序裁，一进预算就停。永远不临时起意地裁。

1. **装饰单元**——便签、游离文字、标题块、水印、源自带的图例。（值得保留的便签转为旁注：serif 正体，≤2 处。）
2. **完全重复**——N 个相同的 worker / 副本 / 分片合成一个节点，标 `Worker ×N`。
3. **叶子簇**——子节点全是叶子的容器折叠成容器本身：三个盒子变一个「核心服务」。
4. **不改故事的出度为 1 的挂件**——监控钩子、日志桶、归档层。
5. **横切基础设施**——日志、指标、密钥、CI。`simplified` 直接去掉不问；`balanced` 最多留一个，且仅当图就是讲它的。
6. **还超？** 拆总览 + 细节。拆永远赢过缩。

第 2–6 步裁掉的都要进保真台账（§5）。第 1 步不用报。

---

## 4. 受众级别

与细节盘独立：同样 12 个节点，给平台团队和给指导委员会起的名字不一样。细节定**多少个**；受众定**叫什么**。

| 受众 | 节点名 | 子标签 | 连线标签 | 禁止 |
|---|---|---|---|---|
| `engineer` | 精确的服务 / 组件名 | 协议、端口、版本、镜像 tag | `POST /v2/orders`、`SQL`、`gRPC` | "连接到"这类含糊动词 |
| `mixed`（默认） | 组件名，缩写展开 | 只在影响决策处给技术 | 平实动词——校验、写入、通知 | 端口、版本、内部代号 |
| `executive` | 能力与结果 | 无 | 业务动词——审批、放款 | 供应商名、基础设施、协议 |

同一节点过三级的实例：

| 受众 | 节点名 | 子标签 |
|---|---|---|
| `engineer` | `认证服务` | `JWT · RS256 · :8443` |
| `mixed` | `认证服务` | `token 校验` |
| `executive` | `登录` | — |

所有受众级别都成立的两条规则：

- **永远不为填槽编造细节**。源里写 `svc-04`，`executive` 输出只在上下文能判断时才写它干什么——否则问，不要猜一个业务名。
- **专有名词保留源词汇**。`Kafka` 在 `executive` 改叫「消息队列」可以；改成「Event Grid」（另一个产品）是事实错误。

### 拉丁标签与混排

本技能的皮肤原生覆盖中文，无需为汉字加兜底。规则只有三条：

- 纯拉丁技术子标签走 mono 栈；含汉字的子标签走 sans 栈且 **≥10px**（汉字低于 10px 会糊）。
- 同字号汉字比拉丁宽约 10%——节点宽度按中文名称预算（SKILL.md §7.5 宁宽勿挤），不要按英文长度估。
- 中英混排手动加空格：`认证 JWT`、`5 分钟`。

## 5. 保真台账

输出小于输入的每一次——所有 `balanced`、`simplified` 跑批和多数 `faithful`——在文件路径之后、对话里报告裁了什么。简短、具体：

```
细节：balanced · 源 18 节点 → 画 9 个
合并：worker-01..06 → "接入 Worker ×6"
折叠："可观测性"组（Grafana、Loki、Tempo）→ 一个节点
丢弃：2 张便签、CI 流水线（横切基础设施）
完整保留：请求主链路（客户端 → 网关 → 订单 → Postgres）
```

看图的人看不见缺了什么。要图的人需要知道。

## 6. 清单

与 SKILL.md §10 交付前自检一起过。

- [ ] 四个刻度盘都已设定——用户明说、按投放地推断、或用默认并说明？
- [ ] `viewBox` 与尺寸预设完全一致，数值能被 4 整除？
- [ ] 字号坡道匹配尺寸级别——没有把 standard 坡道用在幻灯上？中文 ≥10px 未被坡道压破？
- [ ] 40px 外边距（`social-og` / `wechat-cover` 为 64px）守住了？
- [ ] 节点数在细节级别上限内？
- [ ] `faithful` 超 9 节点已分区；超 24 已拆图？
- [ ] 节点名、子标签、连线标签在同一个受众级别上？
- [ ] 裁过的内容都进了保真台账？
- [ ] `<svg>` 有 `role="img"`、可解析的 `aria-labelledby`、非空首子 `<title>` 与 `<desc>`、且 id 前缀等于文件名 slug（SKILL.md §13）？
- [ ] 非 HTML 格式经 [`export.md`](export.md) 产出，不是手写的？
