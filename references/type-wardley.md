# Wardley 地图

**最适合**：把价值链的组件对着**演进程度**（商品化程度）定位，让读者看得出什么该自建、什么该外购、什么即将移动。它是战略产物不是架构图——不讲组件运行时怎么连接，只讲每个组件落在创世到商品曲线的哪里。

## 布局惯例

- **纵轴——价值链。**「用户可见」在上，「不可见」在下。轴端标签用分行横排的 `<text>` 叠在轴端两侧——**绝不 `writing-mode` 竖排**。轴线 `ink @ 0.20` 1px。
- **横轴——演进。**四条带、三道竖发丝线分开：`创世 | 定制 | 产品 | 商品`。带分隔线 `rule @ 0.10` 虚线 `4,4` 0.8px；带名沿底轴居中（中文角标档：sans 12px · 500 · 0.3em）。横轴线同 `ink @ 0.20`。
- **组件** = r=6 圆点，纸底 + `ink` 1px 描边。标签 sans 12px · 600，点位上方 12px、锚中。技术限定词可用 mono 9px `muted` 子标签挂在点下——克制使用。
- **依赖线** = `muted` 0.8px 细直线，从组件连到它依赖的组件。**这是全技能对 §8 规则 1（强制正交肘）的明文豁免——仅限依赖线。** 组件在图上的 y/x 位置**就是数据**；为凑直角肘把它挪到轴上等于改数据。无箭头——线本身就陈述了依赖。
- **演进箭头**——正在商品化的组件带一段向右短箭头：`accent` 虚线 `5,4` 1.5px，`marker-end` accent 箭头，从圆点边缘指向下一条带。**不配箭头文字**：图例的「演进中」样（accent 点 + 虚线箭头）已经命名了 accent + 虚线的含义，且本图箭头只许向右（见反模式），方向本身就是「朝商品化」——再写一个「商品化中」是把形状与颜色已承载的信息复述一遍，按 §1 删除测试，删的是标签不是位置。
  箭头配字只在**限定**箭头自己说不出的东西时合法——时限（`Q3 前`）、动因（`厂商锁定`）——绝不是复述方向。要加就按 §8 规则 3 垫纸色遮罩（mono 8px、净空 6–10px），先确认遮罩有落脚处：圆点正下方是全图最挤的地方（依赖线也从那里扇出），上方又常被组件自己的名字占着——两处都不净空就不加，图例已经覆盖。
- **焦点规则**：2 个 accent = 演进组件的圆点（`accent-tint` 填充 + `accent` 1.5px 描边）与它的演进箭头；或两个演进组件分占这 2 个位——图上其余任何地方不许再有 accent。
- **图例**：底部横条按通用规格，三项：组件 / 依赖 / 演进中（accent 点 + 虚线箭头样）。

## 复杂度预算

| 上限 | 规则 |
|---|---|
| 组件 | 9 |
| 依赖线 | 12 |
| 演进箭头 | 2 |
| accent 元素 | 2 |

## 反模式

- **把横轴当成熟度打分。** 演进是四条定性带（创世 / 定制 / 产品 / 商品），不是 0–10 滑条——别把组件标在「6.5」上，放进带里。
- **无依赖线的组件。** 价值链里没谁依赖它、它也不依赖谁——它就不在链上，删掉或连线。
- **向左的箭头。** 演进只朝商品化走，左指箭头是矛盾不是设计选择。
- **拿它当架构图。** 没有请求方向、没有协议、没有运行时拓扑——那些是架构图的事。本类型回答「自建还是外购」，不回答「流量怎么走」。
- **纵轴标数字。** 价值链可见性是序数（更可见 / 更不可见）不是量，数字刻度暗示一个不存在的测量。
- **超过 2 支演进箭头。** 再多就不是单一论点，是一张没人能行动的预报。
- **`writing-mode` 竖排轴标签。** 分行横排叠字。
- **演进箭头配复述方向的标签。** 「商品化中」说的就是箭头本身——删标签不删位置。
