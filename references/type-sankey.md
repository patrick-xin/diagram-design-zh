# 桑基图 / 流量分配图

**最适合**：一个**数量**在少量阶段间拆分与汇合的去向——算力预算、成本或人力分配、漏斗邻接的量流。这是唯一一种**带厚度本身承载数据**的类型；读者不需要比较量大小时，用 [流程](type-process.md) 或 [金字塔 / 漏斗](type-pyramid.md)。

## 布局惯例

- **恰好 3 个阶段列**，左 → 右，不多不少——超 3 列拆成两张连环图（总览 列1→列2 + 细节 列2→列3）。
- **节点 = 竖条**：宽 12、实色 `ink` 填充、无描边。高 ∝ 通过量，取整到 4px 网格——取整是渲染步骤不是改数据，真实数值仍印在数量子标签里。
- **流 = 填充带**，不是描边线：每条流一条闭合 `<path>`。上缘是从源节点顶偏移到目标节点顶偏移的三次贝塞尔，下缘同一条曲线反向；**两个控制点都落在两列的中点 x 上**、各在自己那一端的 y：`C midX,y0 midX,y1 targetX,y1`——这样带才能**水平**离开与抵达，与竖条方正对接。第二个控制点放到目标 x 上（`C midX,y0 targetX,y1 targetX,y1`）会把曲线压塌到端点上，抵达切线退化，每条带都以可见的斜角撞条——像没接上。
- **永远不画箭头。** 方向由左→右列序隐含。这是对 SKILL §8 连接线规则的**显式豁免**：带是面积编码不是连接线，填充带上的 marker 读作噪声不是信息。
- **带填充**：普通流 `muted @ 0.18`（深色档 α 不动）。唯一焦点路径 `accent @ 0.20`。一条焦点路径可以跨多条带（两段流共讲一件事）——同属这条路径的带全部 accent，合算**一处**焦点。永不逐流彩虹——色留给唯一配讲的那条路径。
- **节点排序最小化交叉**：每列内排序使汇入/分出同一节点的流保持一致的上下次序。两条带仍交叉不止一次就重排节点，不许打结。
- **标签**：节点名 sans 12px · 600，数量 mono 9px · `muted` **纯数字**（单位只写一次进口径注——9px 汉字违法）。摆位按列：列 1 在条外侧锚尾；列 2 **居中于带间沟槽**锚中（沟槽是带自己留出的空隙，标签落在干净纸面上，**不要垫遮罩**——填充带上的遮罩读作图上凿了个洞）；列 3 在条外侧锚头。
- **列头**：中文角标档（sans 12px · 500 · 0.3em）居中于各列上方——「预算 / 测试阶段 / 结果」式短语，不写整句。
- **绘制顺序**：列头 → 普通带 → 焦点路径的带（最后画压顶）→ 节点竖条 → 标签 → 图例。
- **图例**：底部横条按通用规格；样块 16×12 与带处理一致（普通带 / 焦点带 / 节点实色），口径注写单位与恒等口径。

## 比例尺规矩

全图**一个** px/单位常数 `k`，所有节点与带宽共用——不许每列各一套。厚度取整到 4px，**在节点层面对账**：一个节点的出流之和恰等于它（取整后的）条高。

**数字可选时选落在网格上的**：k 下一步 4px = 4/k 单位，数量取其整倍数，画出的面积就正好等于印出的数。取整是真实数据的兜底且有代价——面积编码数量的图里，条高与旁边的数字对不上是拿可信度换网格合规。取整永不超过一步 4px，永不取整到节点的带不再求和。

**带最薄 4px**：再薄就并入「其他」带——读者看不见的桑基带什么也没说。

### 参考算例（k = 0.02 px/分钟，月度 12,000 分钟）

| 节点 | 数量 | 高（px） |
|---|---|---|
| 流水线分钟（列 1） | 12,000 | 240 |
| 单元测试 | 5,200 | 104 |
| 端到端 | 4,000 | 80 |
| 构建 | 2,000 | 40 |
| 静态检查 | 800 | 16 |
| 通过 | 9,400 | 188 |
| 失败 | 1,600 | 32 |
| 抖动重跑 | 1,000 | 20 |

每列节点高之和同为 240px——**总入 = 总出**这个恒等式让图一眼可信；两列总和不等，是数据漏了或布局有 bug。

## 几何

三档同构 `viewBox 0 0 1000 520`：列条 x = 120 / 500 / 880（宽 12），列头基线 y=28（顶贴带），首节点 y=72，节点底 408；图例分隔线 = 408 + 56 = 464、基线 482，画布高 520。控制点 x：列 1→2 用 316，列 2→3 用 696（两列中点）。

## 复杂度预算

| 上限 | 规则 |
|---|---|
| 阶段列 | 3 |
| 节点 | 8 |
| 流（带） | 12 |
| accent 元素 | 2（一条焦点路径的全部带合算一处） |

超预算 → 拆两张连环桑基，不硬塞第四列或第九个节点。

## 反模式

- **带以斜角撞条。** 最常见的错法，是控制点错误不是布局错误：两个控制点都归中点 x。斜着抵达的带读作与节点脱开——动摇这张图唯一的断言：这个量流进了那个节点。
- **列 2 标签垫不透明遮罩。** 填充带上的遮罩读作凿洞，还会盖掉压到的条。把标签居中进沟槽，落在干净纸面上。
- **列 2 标签贴沟槽顶。** 居中放，否则大写线碰到上方的条，标签像挂错了节点。
- **条高与旁边数字对不上。** 见比例尺规矩：数据可选就选网格友好的数。
- **带交叉不止一次。** 重排出错列的节点；中间打结的桑基没法读。
- **比 4px 还薄的带。** 并进「其他」带，别画没人看得见的细线。
- **逐流彩虹。** 普通流一个 muted 处理、焦点流一个 accent 处理，绝不一带一色。
- **单一收窄量用桑基。** 不拆不分只有一个越走越窄的量——那是金字塔 / 漏斗。
- **纯步骤链用桑基。** 不拆分、不汇合、厚度不变就是流程图——桑基的存在理由是会分叉的数量。
- **两条流叠同一节点偏移。** 每条流在节点高内有自己的偏移区间，上下次序一致——绝不两条带共用一个附着点。
- **百分比 / 数量对不上源总量。** 每个节点的出（入）流之和必须等于它自己的高。不平衡的桑基读作错误，不是设计选择。
