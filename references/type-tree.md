# 树形图（Tree / Hierarchy）

**最适合**：组织结构、依赖树、分类学、文件树、决策分解、技能树——**通用**的父子层级。

节点是人 / 角色 / 团队 / 责任人时改用组织架构图（type-org-chart.md）：树只讲结构，组织图讲归属、调用路径与覆盖缺口。

## 布局惯例

- 根在上、子级向下展开（或根在左、子级向右）。
- 节点 = 小标签矩形（`rx=6`）：中文节点名 sans 14px 600 + 可选技术副标 mono 10px。宽 120–180px、高 40–52px。
- 节点内文字垂直留白：副标基线距盒底 ≥6px，整块文字在盒内上下大致居中——别让副标贴着下边框。
- **模板密度：根 + 3 个一级分支、每支 ≤2 片叶（共 9 个节点封顶）。** 示例按这个密度打样；更密的树是用户自己的复杂需求，让用户向 agent 单独提。
- **连接线正交（肘线），绝不斜线，且必须压准**：父节点垂下的竖线落在父盒中心 x，横总线两端对齐最左 / 最右子盒中心 x，每个子盒再垂直接入自己的上边中点。画完逐个端点对账。1px `muted` 描边。
- 同层节点盒之间留 ≥16px 间隙，整层收在画布边距内（右缘 ≤960）——叶子一挤就先砍分支数，不缩盒子。
- 叶子标识：细描边（0.8）或不同填充——或干脆让「末端位置」自己说话。
- 深度上限 4（根 + 3 层）；每层宽度上限 5。
- **accent 只给一个节点**：根**或**关键叶子，不给两个。
- 连接线先画，节点后画。

## 反模式

- 一页画 5 层以上（不可读——拆）。
- 分支贪多：一级塞 5 个、叶子盒互相重叠或挤出右缘——密度超了就砍，不是缩盒子。
- 连接线端点没压准盒子中心（悬空 / 偏移半个盒宽）。
- 节点宽度悬殊——至多两档宽度。
- 斜连接线。
- 跳层连接（父直连孙，中间层消失）。
- 根和叶子同时上焦点色。
