# 泳道图（Swimlane）

**最适合**：跨职能流程、RACI 式职责流、供应商交接、多团队协作的发布流程。

## 布局

- 横向泳道（或纵向泳道）——每个角色/团队一道。左侧留一条**角色列**（竖线隔开），道标签放列内：中文 sans 10px · 500 · 0.3em；纯拉丁角色名用 mono eyebrow。
- 道分隔线：1px 发丝线，**外框重（ink @ 0.22）、内线轻（ink @ 0.10）**，角色列竖线同外档。
- 流程步骤 = 矩形，放在**执行该步骤的角色道内**；箭头表达流转。
- **连接线是泳道图的例外词汇**（不受 SKILL.md §8 正交肘线约束）：道内流转 = 水平直线；跨道交接 = **直线斜穿**，从源盒边缘直连目标盒边缘；复核 / 退回类 = 虚线（`4,3`，闭集）；关键交接 = `accent` 1.4px。泳道线与图例横线右缘贯通 0→1000；图例锚 = 道底 + 56。绝不绕肘线。
- 箭头小签：白底矩形遮罩线身 + 中文 sans 10px · 500 说明（「交接」「复核」「下单触发」式短语），关键交接的小签用 accent。
- **交接（跨道箭头）是最重要的边**——考虑把焦点色落在引入最多耦合或等待的那次交接上，或落在流程的终点步骤。
- 不强求每道步骤数相等；一道只有一个步骤是正常的。
- 为让流转基本走直线，宁可重排步骤也不让箭头蛇形往返。

## 反模式

- 没有标签的道
- 一个步骤骑在两道上（必须选一个 owner）
- 跨道交接绕正交肘线——泳道图里直线斜穿更有力，肘线留给通用流程图
- 箭头来回蛇形——重排步骤让主流程大体直线推进
- 交接箭头无标签（交接点通常需要说明交付物或条件）
- 用颜色区分步骤归属——道已经表达了归属，颜色只留给焦点
