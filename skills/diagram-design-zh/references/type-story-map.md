# 用户故事地图

**最适合**：Jeff Patton 式用户故事地图——回答「整个故事是什么，第一版在哪里切」。叙事顺序自左向右，优先级自上而下；**发布切线**是全图的编辑论点——没有切线的故事地图只是网格里的待办清单。

与两个近亲的分工是承重墙：

- [看板](type-kanban.md)讲**状态**——列是待办 / 进行 / 完成，没有叙事序也没有可切的片。
- [用户旅程](type-journey.md)讲**一个画像的感受**——靠情绪曲线。
- 故事地图两者皆无：列是**叙事顺序**，行是**发布切片**。不切发布就用那两个。

## 布局惯例

纵向堆叠，自上而下五层：

1. **骨干**。最多 5 个活动卡自左向右按用户经历的叙事序排（宽卡 `rx=6`，`ink @ 0.05` 填充 + `muted @ 0.60` 描边）。卡内：活动名 sans 12px · 600 在上，角标「活动 N」在下。
2. **行走骨架**。每个活动正下方挂用户**步骤**小卡（`rx=4`、32 高、backend 档：纸白 + `ink @ 0.40`），sans 12px。每活动一到两步，**预留两行的空间**——只有一个步骤的活动行底也对齐。
3. **发布切片**。骨架行下方的整宽行带，道底交替 `ink @ 0.02` / 无；切片标签在左缘横排（`MVP` mono 8px · 0.18em；中文切片 sans 12px · 0.3em），按**范围**命名（MVP / 第二批 / 后续），不按日期命名——`Q3` 描述的是日历，排期一滑就漂。行带内的故事卡（`rx=4`、48 高、backend 档）落在各自活动列：故事标题 sans 12px · 600 + mono 9px 估算子标签（`RPT-114 · 3pt`）。任何切片有空洞（该行某活动没有卡）时，补 `rule` 虚线 `4,4` 列分隔（0.8px），从骨干下方通到末片行底、**先画卡后画线之上**——没有它们，稀疏网格读作散落而不是钉在活动列上。
4. **发布切线**。紧贴 MVP 行带下方的整宽 `accent` 横线（1.5px），右端纸色遮罩上标签「发布切线」（sans 12px · 500 · 0.12em `accent`）。这是焦点一。
5. **图例**。底部横条按通用规格：故事卡 / 风险最高 / 发布切线三项。

## 焦点规则

恰好 2 个 accent：发布切线（含标签，算一处），和唯一最高风险故事卡——`accent @ 0.05` 填充 + `accent` 虚线 `4,4` 描边 + 右下角「风险」小角标（`rx=2` 芯片，10px `accent`）——算另一处。图上其余一切不带 accent。

## 几何

三档同构 `viewBox 0 0 1000 560`（四活动版）：骨干卡 x = 80 / 308 / 536 / 764（宽 204、沟 24），活动卡 y=16..80；列分隔 x = 68 / 296 / 524 / 752 / 980、y = 84..472；步骤卡 y = 96 / 136（两行）；切片行带 y = 184 / 296 / 392（各高 80，一三铺道底），故事卡 y = 行带 + 16、高 48；发布切线 y = 280；图例分隔线 = 末片行底 472 + 56 = 528、基线 546，画布高 560。

## 复杂度预算

| 上限 | 规则 |
|---|---|
| 活动数 | 5 |
| 发布切片 | 3（MVP、下一批、以后——再多没人信排序，尾巴并进「后续」） |
| 故事卡总数 | 12 |
| 单切片卡数 | 4 |
| accent 元素 | 2（切线、风险卡） |

单活动或单切片超预算 → 按活动拆多张地图，或把一片折叠成计数卡，不逐条硬列。

## 反模式

- **没有发布切线。** 没有切线的地图是网格里的待办清单——切线就是全图的全部意义。
- **列按优先级而不是叙事序排。** 骨干是一个故事，按用户经历的顺序自左向右——不是排行榜。
- **故事卡写成功能而不是用户可见的结果。** 「加一张图表」是故事；「重构图表服务」是后台工单，进待办不进地图。
- **切片按日期命名。** `MVP / 第二批 / 后续` 描述范围；`Q3 / Q4` 描述日历，排期一滑就漂。
- **超过 3 个切片。** MVP、下一批、以后之外没人相信排序——尾巴并进「后续」。
- **一张图混两个画像。** 与用户旅程同规矩——一图一画像。
- **加状态列。** 那就成看板了——本类型没有状态。
- **加情绪曲线。** 那就成用户旅程了——本类型没有感受轴。
