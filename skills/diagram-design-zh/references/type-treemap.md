# 矩形树图（Treemap）

**最适合**：部分与整体，且**相对大小就是故事**——磁盘与依赖包占用、预算拆分、市场份额、人口、时间分配。一个总量分解成数块、读者的问题是「谁占大头、大多少」时用。

不用它：排名清单且精确值比占比重要（**柱状图**）；表达包含 / 作用域但没有数量（**嵌套图**）；需要逐层追父子路径（**树形图**）。

## 布局惯例

- **绘图区铺满容器**（无轴图型不设边距）：格子区 x 0→1000、y 0→380，viewBox `0 0 1000 480`——左缘贴标题线、右缘贴画布边；图例横条锚 = 格子底 380 + 56 = 436，条目基线 454，数据源行右锚 x=1000。
- **Squarified 布局**（Bruls 等，2000）：降序排列，每行贴剩余矩形的**短边**排。长宽比保持接近 1，两块面积才能用眼睛比。**绝不排成简单条带**——细长条没法比。
- **格子数**：4–8。超过 8，尾部变成没法标注的细条——把尾部并进一个明确的「其他」格，并在数据源行写明含什么。
- **4px 网格**：格边像一切元素一样贴网格，格间 4px 泳道。贴格与泳道都会挪面积，所以交付前要核——按**相对误差**核（`(绘制 − 真实) ÷ 真实`），不看百分点。59% 的格差 0.1pp 无所谓，0.5% 的格差 0.1pp 就是四分之一。每格控制在真实占比的几个百分点内（官方示例最差 2.7%，正是那条细格——网格做不到更好），并把编码写进数据源行（`面积 = 存储量`）。
- **填充**：按名次排的 `ink` 透明度梯——档位 = style-guide α 梯子的图表特例 `{0.16, 0.13, 0.11, 0.09, 0.07, 0.04}`，六档整组使用（值编码面积深度，不许单抽一档、不许发明组外档）——非焦点的次序在灰度打印和色弱读者下都活着。焦点格至多一个——最值得看的那块，不自动等于最大的。注意焦点格被摘出了色梯，灰度下落在哪算哪；靠 `accent` 描边识别它，绝不让色阶承载面积以外的含义。
- **描边**：每格 1px `ink @ 0.30` 发丝线；焦点格 1.4px `accent`。
- **标签放格内**，左上角、离边 16px：格名中文 sans 14px 600（窄格 12px），下一行数值 mono 9px。按格大小分四档：
  - 大格——名 + 值 + 占比（`4.78 TB · 59%`）
  - 中格——名 + 值
  - 小格——一个诚实的短缩写
  - 细条——**不放字。** 格子至少 12×12px 时，格心放一个实心 `ink` 圆点 `r=5`、内嵌 paper 色 `i`，格名与占比写进图例；两边都不足 12px 就省掉格内标记，靠图例里的位置说明。定尺寸的圆点绝不许压格边。**不要为塞下标签旋转文字**：五个正字里躺一个侧字，读者先看到失误再看到数据；而且 `text-anchor="middle"` 沿基线居中，转 90° 后基线映到长轴，窄轴方向没有任何东西在居中。
  - 绝不为标签缩格。格的大小是数据，标签是注解。
- **对比度**：按实际交付的 token 算天花板。数值行是 mono 9px `muted` 不是 `ink`——`muted` 需要比 `ink` 更浅的格底：对着合成后的填充实测，浅色档色梯顶部到 **0.16**、深色档到 **0.14** 就跌破 4.5:1（`ink` 能忍到 0.20——查错 token 恰好会写下这个数）。中间调填充（实心 accent 或 50% ink）对深浅文字都挂；用「淡染 + 描边」套路。数据源行同样用 `muted`：`soft` 在纸上只有 3.48:1，在这条色梯上到不了 AA。
- **图例**：标准块（发丝线、`LEGEND`、条目）——点名焦点格、色梯方向、带信息圆点的格。数据源行与 `LEGEND` 同行右对齐 mono 9px，写清面积编码的是什么 + 数据集与日期。

```svg
<text x="X+16" y="Y+46" fill="#565e7e" font-size="9"
      font-family="'Sarasa Mono SC', ui-monospace, monospace">VALUE · SHARE</text>
```

焦点格：填充换 `accent@0.15`、描边换 `accent` 1.4px。

## 诚实数据规则

**面积是唯一编码。** 不裁切、不设下限、不取对数来让格子可见；也不因为格子小就删格——树图声称展示一个整体，少一块图就在撒谎。小到没法标注的部分给图例条目，格内只在装得下时给信息圆点；小到画不出的部分并成一个诚实的、有名字的「其他」。好几块在目标尺寸下都看不见，说明这份数据想要的是柱状图。

最小格盯最紧：贴格与泳道对它扭得最狠，也最没人核。展示的**舍入**同样要防：六个值各自进位，加起来可能超过你印在下面的总量。要么保留足够精度让各部分对得上账，要么在数据源行直说（`数值经舍入，合计可能有出入`）。

## 变体

### 马赛克图（Marimekko）

**最适合**：**双向的部分与整体**——两个拆分都重要、读者的问题是「交叉表里哪一格主导」：云开销按产品线 × 资源、包体积按包 × 分块、支出按团队 × 供应商、事故按服务 × 严重级。树图回答一个问题（谁占大头）；马赛克图一次回答三个：横向读类目占比、纵向读列内构成、面积读联合份额。等宽的百分比堆叠柱保留列内构成但丢掉类目大小；树图保留联合大小但丢掉网格。不适合：单向拆分（那是树图，单系列的马赛克图就是柱状图）；比较各列的系列总量（高度编码故意隐藏了它——要这个读法用分组柱状图）；单位不同的系列（没法共用一列）；超过 5 系列 × 8 类目（两个方向都变成没法标注的细条）。

- 与树图同门布局：格子区铺满画布 x 0→1000、每列全高 y 0→380。**列宽 = 类目占全体份额**，列宽预算 = 画布宽减全部泳道（示例 984 = 1000 − 4×4px）；列边贴 4px 网格、泳道恒定——变宽的缝会被读成变窄的列。列名与全体份额印在格子区下方（mono 10px、列心居中、基线 y=402），让宽度可读成数字；窄列（<40px）不印 caption，列名、数值与份额并进图例条目。 图例按样式指南锚定：示例分隔线 y=464，画布高 520，caption 墨迹底至分隔线间距落在 56±4 单位内。
- **每列全高、段纵铺无间隙**，段间只隔 1px 发丝描边；**段高 = 系列在列内的份额**——同一高度即同一列内份额，无论列多宽。段高贴 4px 网格（树图同款对账哲学）：按相对误差核（`(绘制 − 真实) ÷ 真实`），最差段写进口径（示例 4.2%）。
- **系列序全图固定**（按系列总量降序，大者在上）。**缺席的系列省略、绝不画零高**——零高矩形是一格声称存在的数据，省略是一段图例能解释的空白；列间行不齐是特性不是缺陷，所以每段印自己的份额。缺席在该列 caption 点名（`· 无存储段`），语义（未采购、未部署）写进口径或图例。
- **预算**：3–8 列 × 2–5 系列。列宽装不下标签时：格心放信息圆点（树图范式，至少 12px 宽），列名与数值进图例——列的诚实宽度保住；马赛克图声称展示一个整体，删一列就让其余份额全成谎话。
- **标签放段内**左上角离边 16px，按段高分档：≥56px 全标（系列名 sans 12px 600 + 数值行 sans 10px——数值含「万」等汉字时 10px 是汉字下限，树图数值行的 9px mono 是纯拉丁特权）；32–55px 紧排（名 11px + 数值 10px）；更矮不放字。焦点段可加「占某列 83%」——那是读者最易误读成全体份额的数。**绝不为标签缩放段、绝不竖排文字**。
- **颜色：坡道按系列、不按格**——每个系列一个固定 α 跨全图一致，一行读作一个东西：系列坡道 = ink@`{0.16, 0.10, 0.05}` 三档整组（按系列总量降序取档），图例一键一系列、不写方向词。焦点段至多一个：`accent@0.15` + accent 描边 1.4px（树图焦点格同款），摘出坡道外。深色档换基 α 不动。文字 ink（名）/ muted（数值）。
- **诚实数据**：宽、高、面积是同一张表的三种陈述，全都要对账——列放宽了是在类目上撒谎，段垫高了是在系列上撒谎，任何一个都在联合份额上撒谎。不删类目不删系列（尾部并进有名字的「其他」）；单位、周期、总量写进数据源行，示意数据直说；各值分别舍入后合计可能对不上声明总量——保留精度或直说。

## 反模式

- 超过 8 格没有「其他」桶（细条没法标注）。
- 各格加起来不等于声称的总量；百分比列合计不是 100。
- 条带布局而非 squarified——面积对比失效。
- 彩虹填充：一格一色毁掉名次阅读和单焦点规则。
- 静态图里嵌套超过两层；第二层要更重的边框和自己的标签档，第三层没有交互就读不了。
- 3D 或带阴影的格——面积已经是全部信息了。
