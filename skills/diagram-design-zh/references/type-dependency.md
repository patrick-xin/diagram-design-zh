# 依赖图

**最适合**：谁依赖谁——跨包、跨模块、跨服务。专门表达**树形图结构上画不出来**的两件事：(a) **多亲节点**（一个共享依赖被几方汇聚引用）；(b) **环**。数据里两者都不出现——每个节点恰好一个亲、没有回指——就用[树形图](type-tree.md)，并且**明说换类型**，不硬把树形数据塞进图布局。

**标签语言（2026-08-29 定）**：**盒内小标签保持拉丁 eyebrow 档**——层标 `RANK 0..3`、入度徽章 `N IN`、类型角标 `APP / SVC / PKG / EXT`、环标签 `CYCLE` 全走 mono 7–8px 拉丁档。原因：家族芯片尺寸（28×12 等）锁死，中文最小 10px 会撑爆芯片，放大芯片又连带节点盒与整图布局，得不偿失。说明性文字（图例项、标题、口径注）用中文；包名、路径、版本（`packages/ui-kit`、`v3.23 · npm`）是代码本体原样保留。

## 布局惯例

- **rank 分层。** 节点按依赖深度排水平层：第 0 层（无人依赖的入口）在顶，越深越往下。前向边跨层向下，或依赖被压缩到同层时同层横走（如浅层兄弟依赖）——除标记的那条环外**永不向上**。层间距 120。层标贴画布左缘 x=0（mono 8px · 0.18em，拉丁 eyebrow 档）。
- 节点走标准节点盒（SKILL §6）：`rx=6`，160×56。
- **入度徽章。** 每个节点右上角带小芯片（`rx=2`，描边 `ink @ 0.40` · 0.8px，28×12），写 `N IN`——多少个节点依赖它（mono 8px 纯拉丁）。完全落在节点内的芯片是徽章不是标签，§6 规则 6 下合法。**入度最高的节点就是全图的结构故事**——不要给别的元素加尺寸或权重跟它抢。
- **节点三处理**（style-guide 节点表）：
  - 内部包 / 服务 → `backend`：纸面填充 + `ink @ 0.40` 描边。
  - 外部 / 第三方 → `external`：`ink @ 0.03` 填充 + `ink @ 0.30` 描边。
  - 无出边叶子 → `store`：`ink @ 0.05` 填充 + `muted @ 0.60` 描边。
- **环。** 至多一条回边逆层向上。它是全图的编辑点：`accent` 描边、虚线 `5,4`、`marker-end` 指向被回指节点，路由**绕节点堆外侧**——绝不直穿中间、不藏在它不连接的节点后面——可见端带 `CYCLE` 标签（mono 8px · 0.06em，paper 遮罩）。环触碰的两个节点保持常规节点处理——节点自己上 accent 或焦点填充就是把 2-accent 预算花错元素。
- **焦点规则**：2 个 accent = 回边 + 它的 `CYCLE` 标签。依赖图里其余一切不 `accent`。
- SKILL §8 六条连线规矩全部适用、零豁免：圆角直角肘（r=8）、标签遮罩净空、交越跳线（次要线跳）、同盒多边扇出 ≥12px、连线不穿非端点盒。

## 复杂度预算

| 上限 | 规则 |
|---|---|
| 节点 | 9 |
| 边 | 14 |
| 层数 | 4 |
| 高亮环 | 1 |
| accent 元素 | 2 |

超预算：把一簇叶子折叠成一个带计数的聚合节点（如「+6 叶子」），并在标题里说明——不静默丢节点。

## 反模式

- **数据本来就是树还画依赖图**（处处单亲、无环）——用树形图。
- **未标记的环之外出现向上的前向边。**
- **不排 rank 的毛线球布局。** 先分层、永远先分层——可读性来自分层，不是可选的抛光。
- **一个文件一个节点**而不是一个包 / 模块 / 服务一个——图画的是依赖结构，不是文件系统。
- **无标注的外部依赖。** 版本与来源属于子标（`v3.23 · npm`），不留隐式。
- **一张图高亮两个环。** 挑编辑上要紧的那个；第二个环跟第一个抢注意力，两个都读不出来。
- **漏掉入度徽章。** 没有徽章读者一眼看不到依赖在哪里汇聚——这正是这个类型相对树形图的存在理由。
