# 品牌接入（onboarding）

把用户的品牌色与字体提取出来，写入 `style-guide.md` 的语义角色。只在用户明确选择定制时执行；**写入前必须先给出旧值→新值的 diff 提案，用户确认后才动文件**。

## (a) 从网站 URL 提取

1. 抓取首页 + 一两个关键子页的 HTML/CSS。
2. 提取：主色、辅色、背景色（CSS 变量、`meta theme-color`、logo 用色）、标题字体、正文字体。
3. 映射到语义角色：
   - 背景最浅色 → `paper`（**不得纯白**，太白就压暖/压灰一档）
   - 最深文本色 → `ink`
   - 最具辨识度的品牌色 → `accent`（**只取一个**；品牌有多个色时选焦点色，其余降为 muted 变体）
   - 无明确链接蓝 → 保留默认 `link`
4. 字体：品牌拉丁字体接入对应栈首位，中文回退与系统兜底**原样保留**（三栈结构不许破坏）。
5. 输出 diff 提案（角色 | 旧值 | 新值 表格），确认后写回。

## (b) 从截图 / 海报 / PPT 页提取

1. 读图，提取三类色：背景、主文本、强调色；判断字体气质（衬线 / 无衬线）。
2. 同上映射。**对比度必须实算**：`ink`、`muted` 对 `paper` 达 AA；`accent` 作描边 ≥3:1、作文本 ≥AA——不达标就把该色加深/减浅一档再提案，不允许"看着差不多"。

## (c) 从本地文件夹提取

1. 扫描给定路径下 CSS / JSON / Markdown 里的颜色与字体变量。
2. 同上映射 + diff 提案。

## (d) 手动

用户直接给 hex / 字体名 → 同样过对比度检查 → diff 提案 → 写回。

## 写回与约束

- 只写 `style-guide.md` 的 token 表，保持语义角色结构不变。
- 不可破坏的约束：WCAG AA、一个 accent、无彩虹（品牌 8 色也只取 paper / ink / accent 三主色 + 派生）、三栈纪律、背景不纯白。
- 新中式皮肤不受品牌定制影响（自带完整色板，见 `skin-xinzhongshi.md`）。
- 写回后本项目的后续图全部继承，不再重复问。
- 写回完成后提议把这份皮肤 `save` 成命名档案（一台机器服务多品牌，见 [`profiles.md`](profiles.md)）；单品牌用户可不存，工作副本继承照旧。

## 反模式

- 不给 diff 直接改文件——用户必须看到改了什么
- 提取到的颜色全塞进去——超过三个主色就是彩虹
- 纯白背景、删系统字体兜底
- 用品牌色覆盖 `link` 之外的语义角色乱点鸳鸯谱
