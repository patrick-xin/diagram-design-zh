# 部署图

**最适合**：软件**实际跑在哪**——主机、VM、pod、托管服务放进环境或网络边界区里，带副本数与版本化制品。架构图回答「什么跟什么通信」；部署图回答「装在哪台主机、哪个环境、哪条网络边界后面、几副本」。图上没有落位决策可讲——没有区边界、没有副本数、没有要紧版本——就用[架构图](type-architecture.md)；给逻辑架构贴上主机名重画一遍，是部署图最常见的反模式。

## 布局惯例

三层嵌套，从外到内：

1. **区（zone）**——环境或网络边界（`EDGE`、`PROD / CN-HANGZHOU`、`DATA`）。大矩形 `rx=8`，**无填充**（分区不上底色——遮罩才能统一纸色），描边 `ink @ 0.20` 虚线 `4,4` · 0.8px。区名走拉丁 eyebrow 档（mono 7px · 0.18em，环境代码本体），落在左上角**边线下方**（基线 = 区顶 +16）。区**最先画**（z-order：背景 → 区 → 路径 → 节点）。
2. **基础设施节点**——区内的主机 / VM / pod / 托管服务。§6 节点盒 `rx=6`，左上角拉丁类型角标（`POD` / `VM` / `MANAGED` / `CDN`）。处理按 style-guide 节点表对号：**入口 / ingress 类 → `input`（带填充）**；内部负载 → `backend`；托管 / CDN / 第三方 → `external`；存储 / 备机 → `store`；单点或新部件 → `focal`。
3. **制品芯片**——部署到节点上的东西。24 高 `rx=4`，填充 `ink @ 0.05`，描边 `muted @ 0.60` · 0.8px；制品名 sans 12px 居左 + 版本 mono 9px 居右（`v2.4.1`）。一个节点带多个制品时叠放（8px 沟）——sidecar 共置就是这么画的。

**副本徽章。** 跑 N 份的节点在右上角带徽章（`x3`，mono 8px，28×12 芯片）。完全落在节点内的芯片是徽章不是标签（§6 规则 6 合法）。

**网络路径。** 节点间正交圆角肘（SKILL §8），标签写协议与端口（mono 8px：`HTTPS:443`、`TLS:5432`），配 paper 遮罩。**跨区路径 = link 青**；区内路径 = `muted`；异步 / 复制路径 = `accent` 虚线 `5,4`。

**焦点规则。** 2 个 accent = 单点故障或新上线的部件（示例：流复制的主库 focal 填充）+ 它的复制路径（accent 虚线）。没有单点就不带焦点，不硬造。

## 复杂度预算

| 上限 | 规则 |
|---|---|
| 区 | 3 |
| 基础设施节点 | 6 |
| 制品芯片 | 9 |
| 网络路径 | 8 |
| accent 元素 | 2 |

超预算 → 按环境一图，不混。

## 反模式

- **给逻辑架构贴主机名重画。** 看不见落位决策（哪台主机、哪个区、几副本）就用架构图。
- **区只是视觉分组没有边界语义。** 区必须是真实环境或网络边界，不是排版便利。
- **无版本的制品芯片。** 版本是这张图存在的理由之一，无版本芯片是白占的盒子。
- **一个副本画一个节点。** 用副本徽章，不复制节点。
- **云厂商图标汤代替命名节点。** 写主机名或服务名，不贴图标装饰。
- **无标注的网络路径。** 协议与端口是部署图的内容，不是装饰。
- **两个环境混一张图**（staging 与 production 节点并排而没有真正隔离它们的区边界）。
